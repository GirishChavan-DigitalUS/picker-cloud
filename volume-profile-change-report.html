Current VP Architecture (Practical)

  • Path A (existing scheduler indicator): backend/indicators/volume_profile.py computes session POC from closed candles and stores poc inside regular snapshot stream.
  • Path B (new confluence engine): backend/ai/confluence_engine.py fetches yfinance daily bars per timeframe and computes POC + VAL + VAH + pivots separately.
  • Frontend confluence surfaces are wired to Path B API responses, not directly to scheduler Path A outputs.
Observation: The system now has two VP-related calculation paths with different data sources and output scope (POC-only vs POC+VAL+VAH).

Behavioral Impact of Changes

  • Added multi-timeframe confluence context (daily/weekly/monthly) rather than single-session profile only.
  • Enabled pattern classifications like breakout, rejection, in-value-area, and POC tests.
  • Introduced a fused signal score combining VP/pivot confluence and optional AI prediction confidence.
  • Added manual API refresh route for confluence cache invalidation.
  • Exposed confluence strength at both dashboard and detail-panel UX levels.
